# Совместная работа Claude и Codex

Решение OTTO от 28.10.2026: работа делится **по версиям**. Каждая версия целиком у одного исполнителя (Claude или Codex), а её код до «сливай» проверяет другой. Страница с вариантами: https://claude.ai/artifact/Vw68PBXY8zxAL13qdqGra2.

## Правила

1. **Одна очередь.** Каждая версия и задача — GitHub Issue с меткой исполнителя `claude` или `codex`. Задачу с чужой меткой не берём; передача — только комментарием в Issue.
2. **Свои ветки.** Claude работает в `claude/…`, Codex — в `codex/…`. В чужие ветки не пишем, чужие PR не сливаем и не закрываем.
3. **Резерв номеров.** Номер версии и номер миграции базы (`crates/core/migrations/NNNN_*.sql`, он же `user_version`) записываются в Issue версии до начала работы. Кто сливается вторым, перебазируется на `main` и проверяет, что номер не занят.
4. **Перекрёстное ревью.** PR одного исполнителя до показа владельцу проверяет другой. Ревьюер оставляет вердикт в PR («можно сливать» или замечания) и сам код в чужой ветке не правит.
5. **Одно состояние.** Точка продолжения — `docs/project-state.md`. Её обновляет тот, чей PR слит.
6. **Слияние и выпуск.** Слияние в `main` только после «сливай» OTTO для конкретного PR. Выпуск по [releasing.md](releasing.md) делает исполнитель этой версии.
7. **Общие файлы.** `.github/`, `CHANGELOG.md`, версии в `package.json`/`tauri.conf.json`/`Cargo.toml` меняет только исполнитель версии, которая сейчас выпускается.
