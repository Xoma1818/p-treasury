# Ведение репозитория и выпуски

Правила для всех, кто меняет репозиторий (в том числе для Claude в любом треде проекта). Цель: в репозитории только нужное, у каждой версии есть тег, выпуск с установщиком и понятное описание на русском.

## Главное правило

В `main` попадает только то, что владелец (OTTO) разрешил слить. Выпуск делается сразу после такого слияния, отдельного согласия на него не нужно.

## Версии

Номер версии `X.Y.Z`, пока приложение в разработке — `0.Y.Z`:

| Что изменилось | Номер | Пример |
|---|---|---|
| Новые функции, новый экран, миграция базы | `Y` +1, `Z` = 0 | 0.9.0 → 0.10.0 |
| Только исправления ошибок | `Z` +1 | 0.10.0 → 0.10.1 |
| Готовность к постоянному использованию | 1.0.0 | |

Номер стоит в трёх местах и меняется вместе в том же запросе на слияние: `package.json`, `src-tauri/tauri.conf.json`, `Cargo.toml` (`[workspace.package]`). Выпуск проверяет, что все три совпадают с тегом.

Изменения, которые не меняют программу (документы, сборка), версию не поднимают и выпуска не получают.

## Ветки и запросы на слияние

- `main` всегда рабочая: из неё собирается любой выпуск.
- Работа идёт в отдельной ветке и приходит запросом на слияние (PR) в `main`. Если PR зависит от другого, он основан на его ветке и меняет основу на `main`, когда тот слит.
- Название PR — по-русски, что получит пользователь: `0.9.0: курсы ЦБ РФ по кнопке и живой интерфейс`. Для PR без новой версии — без номера: `Порядок в документации`.
- Описание PR следует шаблону `.github/pull_request_template.md`.
- PR создаётся черновиком и переводится в «готов» перед просьбой слить. На каждый PR GitHub Actions собирает пробный установщик (Artifacts запуска).
- После слияния ветка удаляется. Других долгоживущих веток, кроме `main`, нет.

## CHANGELOG.md

- Один раздел на версию, новые сверху: `## 0.9.0` (заголовок — только номер; по нему выпуск находит своё описание).
- Пункты пишутся для пользователя: что появилось и где это найти, без названий файлов и функций кода.
- Раздел пишет тот же PR, который поднимает версию.

## Выпуск

1. OTTO разрешил слить PR с новой версией → PR сливается в `main`.
2. На слитый коммит ставится тег `vX.Y.Z` (например `v0.9.0`) и отправляется на GitHub.
3. Тег запускает `.github/workflows/release.yml`: проверки, установщик для Windows, подпись и файл `latest.json` для автообновления. Выпуск «P-Treasury vX.Y.Z» с описанием из CHANGELOG и строкой о том, как установить, публикуется в открытом репозитории [p-treasury-releases](https://github.com/Xoma1818/p-treasury-releases/releases).
4. Программы, собранные выпуском, сами находят следующую версию по адресу `https://github.com/Xoma1818/p-treasury-releases/releases/latest/download/latest.json`.

Почему два репозитория: код в `p-treasury` закрыт, а файлы закрытого репозитория программа без входа в GitHub скачать не может. В `p-treasury-releases` только README и выпуски, кода там нет и не будет.

Если сборка выпуска упала, тег удаляется (только с согласия OTTO), ошибка исправляется отдельным PR, тег ставится заново на исправленный `main`.

Теги и выпуски не переписываются: вышедшую версию исправляет следующая (`0.9.1`).

## Задачи (issues) и метки

- Ошибка или идея, которую не делаем прямо сейчас, записывается задачей на GitHub, по-русски.
- Метки — стандартные GitHub: `bug` (ошибка), `enhancement` (новая функция), `documentation` (документы). Новые метки не заводятся без нужды.
- PR, который закрывает задачу, пишет в описании `Closes #N`.

## Секреты и настройки репозитория

- `TAURI_SIGNING_PRIVATE_KEY` (Settings → Secrets and variables → Actions) — содержимое файла `p-treasury-updater.key` из общей папки проекта `app-signing/`. Без него выпуск не собирается. Сам ключ в репозиторий не кладётся никогда.
- `RELEASES_TOKEN` — токен GitHub (fine-grained) с доступом только к `p-treasury-releases` и правом Contents: Read and write. Им выпуск публикуется в открытый репозиторий. Когда срок токена кончается, выпуск падает на шаге «Секреты на месте» или публикации — нужен новый токен.
- Settings → General → «Automatically delete head branches» включено: слитые ветки удаляются сами.

## Что не хранится в репозитории

Сборки (`target/`, `dist/`, `installer/`), установщики, файлы базы `*.db`, ключи и пароли, черновики и копии документов. Установщики живут только в выпусках и Artifacts.
