## Постоянные инструкции для эффективности

1. **Один источник задачи.** Сначала проверить существующие Issue/PR и состояние. Работать по проверяемым критериям; не дублировать очередь в нескольких таблицах.
2. **Короткое поручение.** У помощника есть цель, коммит/ветка, разрешённые файлы, зависимости и результат. Он возвращает доказательства координатору.
3. **Нужный состав команды.** Не запускать весь штат. Исследование и независимые области параллельны, общие файлы имеют одного автора. Завершившийся помощник получает следующий этап только при необходимости.
4. **Согласованный контракт.** Для изменения данных сначала определить атомарную команду и поведение ошибок/отмены, затем подключить UI. Не подменять одно действие пользователя несколькими несогласованными сохранениями.
5. **Проверять исходный дефект.** Сначала воспроизведение или конкретный путь ошибки, затем исправление и значимая регрессия. Проверять пересечения функций: чек, заметки, теги, события, валюты и отмена.
6. **Проверки по изменению.** Не повторять тяжёлые прогоны без новой причины; успешная проверка относится к конкретному состоянию. Новый код, сбой или изменение контракта обосновывают повтор.
7. **Свежий независимый взгляд.** Автор не подтверждает собственную реализацию единолично. После исправлений ревью сверяет новый коммит.
8. **Понятные статусы.** В работе → реализовано → проверяется → готово к показу → ждёт «сливай» → выпущено. «Выпущено» подтверждается опубликованными файлами, а «проверено у пользователя» — отдельным фактом.
9. **Записывать коротко.** Обновить задачу, текущий PR и точку продолжения. Важное новое решение — в decisions.md с источником. Результат владельцу — один, с прямыми ссылками.
10. **Явные границы доступа.** Использовать подключённый GitHub с нужным репозиторием. Новые широкие авторизации не запрашивать, если достаточно имеющегося доступа; секреты не читать. Слияние и удаление существующих данных — по правилам владельца.

## Предложения на следующие шаги

- Отдельная проверка ядра и UI уже добавлена в PR 0.17. Следующее улучшение — кеш зависимостей с проверкой воспроизводимости, после оценки первых запусков.
- Короткий проверочный лист перед выпуском с отдельным пунктом восстановления копии и обновления с используемой версии.
- Небольшой показ изменений владельцу на тестовых данных перед каждым заметным выпуском.
- Новые функции после 0.17 выбирать небольшими согласованными пакетами; следующие банки выделить отдельной задачей после стабилизации текущего обновления.

Это предложения по развитию процесса. Неподтверждённые функции и настройки защиты репозитория не включаются в продукт автоматически.
