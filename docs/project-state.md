## Вердикт по 0.17: требуется исправление и повторная проверка

Независимая приёмка выявила четыре пользовательских дефекта на текущем head. Код в рамках передачи не исправлялся.

| № | Проблема | Доказательство и следующий шаг |
|---|---|---|
| QW-1 | «Удалить второй» в возможном дубле показывает сумму части, но может удалить весь разбитый чек | `checks.rs:136,161–165,286`, `transactions.rs:262` в head PR; SQL-воспроизведение на десяти миграциях: показано 1 000 ₽, удаляется 1 500 ₽. Согласовать сущность дубля, исправить и добавить регрессию |
| QW-2 | Сохранение разбитого чека отвязывает заметки | `receipts.rs:137–138` пересоздаёт части, `notes.transaction_id` получает NULL. Проверить сохранение связей и отмену |
| QW-3 | Ctrl+A выбирает только первые 5000 результатов | `Transactions.tsx:90` запрашивает все одним вызовом, `transactions.rs:481` обрезает limit. Нужна полная выборка ID с пагинацией либо отдельной командой |
| QW-4 | Изменение «Поездка или событие» при редактировании разбитого чека не сохраняется | `TxnForm.tsx:156–164,435–446`, `receipts.rs:133–142`: update сохраняет старую связь. Исправить назначение/снятие события и проверить месячный бюджет |

Точные ссылки, сценарии и уровень подтверждения — в [приёмке](handover/2026-10-25.md). Эти номера — внутренние метки передачи, а не номера GitHub issues.
