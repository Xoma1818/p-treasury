# 0.23.0 «Напоминания и платежи наперёд»

Issue #45. Миграция `0015_reminders_ahead`. Расширяет существующие напоминания (`reminders`, `reminder_occurrences`), второго механизма нет.

## Что входит

| № | Функция | Где в коде |
|---|---------|-----------|
| 1 | Несколько сроков «заранее» у напоминания, умолчания в Настройках (`reminder_lead_days`, по умолчанию `3,1`) | `reminders::parse_lead_days`, `due_notices`, `mark_notices`, таблица `reminder_notices` |
| 2 | Напоминание у заметки и события (`reminders.note_id`, `event_id`, ON DELETE CASCADE) | `notes::Note.reminder_id`, `events::Event.reminder_id`, `ReminderButton` |
| 3 | Серия «N раз» (`ReminderInput.count` → `end_date`), последний платёж другой суммы (`last_amount`), правка одного платежа (`amount_override`, `moved_to`), «этот и все следующие» (`split_from`) | `reminders.rs`, `EditOccurrence` |
| 4 | Проверка денег на счёте за `reminder_funds_days` дней (0 — выкл.): открытые платежи по счёту по порядку вычитаются из остатка; только счета в основной валюте | `reminders::shortfalls` |
| 5 | Кнопки «Оплачено» / «Завтра» в уведомлении (tauri-plugin-notification 2.7: `register_action_types`, `on_action`) | `background.rs::register_actions`, `reminders::pay` |

Дата платежа для Календаря и прогноза — `Occurrence.pay_at` (с учётом переноса).

## Решения по умолчанию
- Предупреждения заранее только у своих напоминаний; у займов остаётся `debt_reminder_days_before`.
- Пропущенные сроки (программа была закрыта) — одно ближнее предупреждение, дальние отмечаются показанными.
- «Оплачено» без счёта или категории открывает программу на этом платеже (форма операции), без суммы — просто «выполнено».
