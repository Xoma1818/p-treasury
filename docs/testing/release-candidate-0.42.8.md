# Приёмка установки Kazna 0.42.8

Два независимых задания запускают проверенный x64-установщик из одной сборки на двух чистых виртуальных машинах GitHub с Windows 11 ARM64 и WebView2. Проверяется работа x64-программы под эмуляцией Windows. Для выводов о производительности на физических x64-компьютерах нужен отдельный замер.

## Запуск после подготовки изменений

Открыть [«Установщик для Windows»](https://github.com/Xoma1818/p-treasury/actions/workflows/windows-installer.yml). Для PR из ветки `codex/acceptance-0428` приёмка запускается после сборки автоматически. Для ручного запуска выбрать **Run workflow**, ветку с этой проверкой, включить **Проверить установку 0.42.8 и переход с 0.42.1 в двух чистых Windows 11** и нажать **Run workflow**. Оба задания скачивают `kazna-windows-installer` из текущего запуска. Проверяющий записывает ссылку на запуск и проверяемый коммит.

| Задание | Действие и критерий |
|---|---|
| `Установленная Kazna · clean` | Установить кандидат в чистый профиль, открыть установленную программу. В окне должна запуститься 0.42.8 с новой учебной базой схемы 32. Проверить установочную запись и путь EXE. |
| `Установленная Kazna · upgrade` | Установить официальную 0.42.1, создать учебный счёт, расход, общий и месячный инвестиционные планы. Снять контрольную копию после закрытия программы. Установить кандидат поверх прежней версии и открыть ту же базу. Проверить версию, счёт, операцию, оба плана и предмиграционную копию. |

Старый установщик берётся из [официального выпуска 0.42.1](https://github.com/Xoma1818/p-treasury-releases/releases/tag/v0.42.1). Ожидаемый SHA-256 файла `Kazna_0.42.1_x64-setup.exe` — `e546c60af79e121677d10536aec1f7ca371a3bb5d8bf956f233c97cccf7d62bf`. Для кандидата фиксируется SHA-256 фактического установщика. Идентификатор ZIP-артефакта относится к архиву.

При обновлении отдельная [сверка SQLite](../../scripts/compare-installed-upgrade.py) читает три файла. У эталона и автоматической копии ожидается схема 31, у открытой кандидатом базы — 32. Проверяются целостность, внешние ключи и содержимое всех исходных обычных таблиц, включая число повторяющихся строк. У месячных планов появился столбец валюты, который до подтверждения остаётся пустым. Полнотекстовый индекс заметок является производной структурой, исходный текст заметок проверяется в обычной таблице. Результаты установочных заданий находятся в **Artifacts → installed-0.42.8-clean** и **installed-0.42.8-upgrade**.

## Автообновление из приложения

Эти два задания проверяют установку и обновление уже скачанным NSIS-файлом. Поиск выпуска, подпись пакета, загрузку и автоматический перезапуск проверяют отдельно. После появления 0.42.8 в [публичном канале Kazna](https://github.com/Xoma1818/p-treasury-releases/releases) вернуть чистую Windows 11 к снимку с официальной 0.42.1 и учебной базой. Открыть **Настройки → О программе → Проверить обновления → Обновить**. Дождаться перезапуска, сверить версию, тот же файл данных, остатки и предмиграционную копию теми же критериями. Для репетиции до публикации существует отдельный сценарий с изолированным подписанным каналом. [Матрица W03–W05](windows-11-acceptance.md)
