## Этап 2а. Восстановление старого бюджета

Новый тест `crates/core/tests/restore.rs`: копия из каждой из 15 схем (0.9 … 0.25) с данными примера.

| Проверка | Итог |
|---|---|
| Копия любой схемы проходит «Проверить копию» | да, 15/15 |
| Восстановление: все строки и колонки копии на месте, связи целы, `integrity_check = ok` | да, 15/15 |
| Восстановление даёт ту же базу, что обычное обновление того же файла | да, 15/15 |
| Бюджет, отчёт за период и чистые активы считаются на восстановленных данных | да |

### Найдено и исправлено

| № | Серьёзность | Сценарий | Было | Стало |
|---|---|---|---|---|
| R1 | высокая | «Восстановить из копии» (или перенос с другого ПК) с повреждённым файлом: заголовок цел, страницы данных испорчены | Восстановление проходило, рабочая база заменялась повреждённой; данные спасала только страховка `before-restore` | Отказ «копия повреждена, данные не изменены», рабочая база прежняя |
| R2 | высокая | Копия старой версии, миграция которой падает | Рабочая база оставалась с данными копии на старой схеме (14 вместо 15) — программа работала с неподходящей базой | Копия обновляется в памяти; при сбое — отказ, рабочая база прежняя |
| R3 | средняя | Восстановление старой копии, сделанной при выключенной папке сохранности или с папкой на флешке | Копирование молча выключалось или уходило в чужую/несуществующую папку | Настройки папки сохранности (`vault_on`, `vault_dir`, `vault_synced_at`, `vault_error`) остаются как на этом компьютере; остальное — из копии. Перенос с другого ПК по-прежнему сам выбирает папку, откуда перенесли |

Проверка исправления: `cargo test -p budget-core --test restore` (тесты `damaged_copy_does_not_replace_data`, `failed_migration_of_copy_keeps_live_data`, `restore_keeps_this_computers_vault_settings`) — до исправления первые два падали, после — все 4 зелёные; весь `budget-core` зелёный, clippy без замечаний.

Заодно: замена рабочей базы теперь идёт одним шагом под одной блокировкой (раньше — порциями по 256 страниц).
