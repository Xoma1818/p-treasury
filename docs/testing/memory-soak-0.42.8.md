# Длительный замер памяти Kazna в Windows 11

Цель — выяснить, продолжает ли расти частная память Kazna и её процессов WebView2 при повторении одного маршрута. В [предыдущем замере](undo-feedback-0.42.8.md) после 100 циклов прирост составил 45,2 МиБ. Следующий прогон измеряет память в течение двух часов под нагрузкой.

## Запуск

Нужны проверяемый EXE, установленный драйвер Edge под версию WebView2 и закрытая учебная база за десять лет. Команды выполняются в PowerShell из корня репозитория. Указать фактические пути к файлу программы и каталогу учебной базы. Для ранее проверенной сборки и вымышленной базы команды выглядят так.

```powershell
$env:PTREASURY_BIN = (Resolve-Path 'target/.test-artifacts/undo-0428-stage/layout-bin/budget-app.exe').Path
$env:PTREASURY_VOLUME_DIR = (Resolve-Path 'target/.test-artifacts/volume-0421-20261124/fixture').Path
$env:PTREASURY_MOTION_HOURS = '2'
$env:PTREASURY_MOTION_INPUT = 'dom'
$env:PTREASURY_MOTION_INTERVAL_MS = '2000'
node e2e/measure-motion-lifetime.mjs
```

На время измерения оставить открытым одно тестовое окно в отдельном рабочем столе Windows. Выбрать постоянную тему и обеспечить бодрствование компьютера. Время подготовки и прогрева добавляется к указанной длительности. Для возвращения к прежним 100 циклам убрать переменные `PTREASURY_MOTION_HOURS`, `PTREASURY_MOTION_INPUT` и `PTREASURY_MOTION_INTERVAL_MS` в текущем терминале.

## Что измеряется

Каждый цикл проходит путь «Главная → Операции → новая операция → отмена ввода → Главная». По умолчанию длительного режима новый цикл начинается как минимум через две секунды. Кнопки активируются внутри окна, чтобы драйверу требовалось меньше ссылок на элементы. Вариант `webdriver` использует обычные команды мыши и клавиатуры. Сравнивать серии одного способа ввода при одинаковом темпе.

После прогрева, каждые десять минут и в конце снимаются показатели на Главной в той же теме, без диалогов. Скрипт сверяет остатки по каждому счёту и число операций. В каждой точке записывает частную память и рабочий набор процессов, их количество, память JavaScript, узлы и обработчики, видимость и фокус окна. Поле `collected` показывает, удалось ли перед замером запросить сборку мусора через WebView2. Дополнительно сохраняются число циклов, самый долгий цикл с паузой и медиана, 95-й процентиль и максимум времени действий за интервал. Сортировка, фильтрация, смена темы и сворачивание уже проверяются отдельным сценарием на 100 циклов.

## Как прочитать результат

Для двухчасовой серии предусмотрены исходная точка, одиннадцать промежуточных и итоговая. Если между действиями или во время снятия точки прошло больше минуты при обычном темпе, в журнал записывается `inconclusive` с причиной. Так учитывается и сон компьютера. При другом темпе предел равен трём заданным интервалам между циклами, минимум одна минута и максимум пять минут. После перерыва нужен новый непрерывный замер.

Путь к `checkpoints.jsonl` печатается при запуске. Каждый прогон получает собственную папку внутри `target/.test-artifacts/memory-soak`. Доступен другой родительский каталог через `PTREASURY_MOTION_REPORT_DIR`. Каждая строка записывается на диск сразу. Признак законченного прогона — запись `completed`. При ошибке или остановке клавишами Ctrl+C остаются предыдущие точки. После принудительного завершения процесса последняя строка может быть неполной. Рабочая копия базы и временный профиль удаляются при штатном завершении и обработанном отказе.

Сначала сверить длительность, хеш сборки, число циклов, неизменность экрана и финансовых данных. Сравнить частную память и рабочий набор в МиБ по времени. Учитывать смену состава процессов и необычно большие паузы между точками. Счётчики DOM и JavaScript сравнивать при одинаковом результате сборки мусора. Если после начального роста значения колеблются в одном диапазоне, указать этот диапазон и время наблюдения. Если в последней части серии рост продолжается, привести абсолютную разницу и скорость в МиБ/час. Вывод о долгосрочной утечке требует повторного сопоставимого прогона и установления причины.
