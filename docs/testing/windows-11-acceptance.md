## Артефакты и тестовая база

1. Зафиксировать итоговый SHA из [PR №95](https://github.com/Xoma1818/p-treasury/pull/95). Для быстрой проверки открыть [Windows E2E](https://github.com/Xoma1818/p-treasury/actions/workflows/windows-e2e.yml) → **Run workflow** → ветка `codex/full-test-coverage` → `suite: volume` → `ref`: итоговый SHA. Проверить напечатанный SHA в шаге «Проверяемый коммит». После успешного замера повторить как `suite: full` на том же SHA. Режим `volume` специально пропускает сборку старой версии и проверки замены хранилища.
2. Из [запуска сборки установщика](https://github.com/Xoma1818/p-treasury/actions/runs/44748336852) нужного SHA взять **kazna-windows-installer** и **kazna-windows-portable** после успешной сборки. В протокол внести имя и SHA256 каждого файла. При необходимости выбрать [новый запуск сборки](https://github.com/Xoma1818/p-treasury/actions/workflows/windows-installer.yml). Текущая конфигурация сборки PR может отключать updater при отсутствии ключа. Для проверки полного цикла автообновления нужны два совместимых подписанных пакета и изолированный тестовый канал. Файл `.sig` проверяет подпись Tauri updater. Подпись Windows у EXE проверяется отдельно, например `Get-AuthenticodeSignature -LiteralPath <exe>`.
3. Для `volume` workflow создаёт синтетическую базу примерно на 100 тысяч операций и копирует её во временную папку перед запуском окна. Для ручного обновления использовать чистую Windows 11 VM со снимком и отдельной тестовой учётной записью. Установить старую версию, создать вымышленные счета «Наличные» (3000 ₽) и «Карта» (80 000 ₽), затем расходы с карты 2340, 6230 и 1890 ₽ в одном месяце. До обновления сохранить копию, версию схемы и контрольные значения. Если использовать предыдущий релиз для штатного обновления, испытать смену названия P-Treasury → Kazna отдельно с подходящим старым установщиком.
4. Для этой ручной базы без переводов и долгов ожидаются 3 операции, остаток по карте 69 540 ₽, по наличным 3000 ₽, общий остаток 72 540 ₽, расход месяца 10 460 ₽. После обновления значения и категории должны совпасть. Для отдельной проверки долгов автоматический сценарий `e2e/upgrade.test.mjs` дополнительно создаёт кредит и фиксирует показатели до и после. Образцы и снимки используют только вымышленные данные.

GitHub Actions вернул идентификаторы и контрольные суммы ZIP сборки `ccd2676`. Для самих EXE посчитать хеши после распаковки.

Для W07 на тестовой учётной записи использовать обычный запуск через ярлык. Аргумент `--data-dir` или `PTREASURY_DATA_DIR` отключают защиту от второго экземпляра, поэтому запуск WebDriver с отдельной папкой не подтверждает работу повторного запуска из меню «Пуск».

В журнал каждого прогона добавить SHA и версию приложения, ОС и WebView2, вид артефакта и его SHA256, ID сценария, результат и ссылку на доказательства. Подтверждение установки, обновления, сохранности данных и работы окна фиксировать отдельно. Любой провал обязательного сценария или необъяснённый пропуск оставляет его открытым.
