# Как идёт работа над P-Treasury

Работа устроена как маленькая компания: владелец (OTTO) просит и решает, директор раздаёт задачи, сотрудники делают каждый своё. Схему «В. Смешанный» OTTO выбрал 22.10.2026. Наглядно, с вариантами и сравнением: [страница «Штат P-Treasury»](https://claude.ai/artifact/UwnwMZK978ZCswoqudksa9).

Эти правила действуют для Claude в любом треде проекта. Правила веток, версий и выпусков описаны в [releasing.md](releasing.md), здесь они не повторяются.

## Схема

- **Тред на задачу.** Каждую задачу (версию, исправление, исследование) ведёт свой тред от постановки до готового PR. Внутри он зовёт сабагентов по ролям из `.claude/agents/`.
- **Две постоянные службы.**
  - «Ревью»: независимо проверяет каждый PR перед тем, как показать его OTTO.
  - «Выпуски» (тред 9): сливает PR после «сливай» и выпускает версию.
- **Директор** (координатор в чате проекта) принимает просьбы, заводит треды и держит вкладку «Ход работ».

## Штат

| № | Роль | Где работает | Отвечает | Готово, когда |
|---|---|---|---|---|
| 00 | Директор | чат проекта | принимает просьбы, сверяет с памятью и строкой «СТАДИЯ», заводит треды, ведёт «Ход работ» | у каждой открытой задачи есть тред, процент и понятно, чего ждём |
| 01 | Аналитик | тред задачи (сабагент `analyst`) | постановка: что делаем, зачем, чего не делаем, критерии приёмки | критерии проверяются ответом «да/нет», спорное вынесено OTTO карточкой выбора |
| 02 | Дизайнер UI | сабагент `ui-designer` | вид и тексты: тема «Тёмный графит», подсказки «?», пропорции 1280/1920 | экран продуман в обеих темах, тексты понятны без инструкции |
| 03 | Разработчик ядра | сабагент `core-dev` | `crates/core`: миграции, расчёты, деньги в копейках, импорт, копии | тесты ядра зелёные, старая база обновляется без потери данных |
| 04 | Фронтенд | сабагент `frontend-dev` | `src/`: экраны, кнопки, графики, меню | сборка проходит, экран совпадает с наброском |
| 05 | Тестировщик | сабагент `qa-tester` | `npm run check`, сквозные тесты, снимки экранов | каждый критерий приёмки проверен, проверки GitHub зелёные |
| 06 | Ревьюер кода | постоянный тред «Ревью» (сабагент `code-reviewer` для мелочи) | второй взгляд на разницу в PR: ошибки, данные, миграции, лишний код | серьёзные замечания закрыты, остальные описаны в PR |
| 07 | Релиз-инженер | тред 9 «Выпуски» | слияние, CHANGELOG, `release.yml`, проверка установщика и `latest.json` | выпуск опубликован, ссылка у OTTO |
| 08 | Архивариус | тред задачи + директор | память проекта, строка «СТАДИЯ», `docs/`, `INDEX.md` общей папки, предупреждения зависимым тредам | новый тред продолжит работу, ничего не переспрашивая |

## Маршрут задачи

1. **Просьба.** Директор сверяет её с памятью и идущими тредами: новая задача или дополнение к идущей. Новая задача получает тред.
2. **Постановка.** Аналитик пишет постановку с критериями приёмки и планом по стадиям с процентами. Если выбор меняет цель, OTTO получает карточку с вариантами и рекомендацией.
3. **Макет.** Дизайнер набрасывает экран, если меняется вид. Для мелкой правки шаг пропускается.
4. **Разработка.** Ядро и фронтенд работают в одной ветке треда, открывают черновой PR.
5. **Тесты и снимки.** Тестировщик гоняет проверки, снимает экраны в `updates/X.Y.Z/` общей папки.
6. **Ревью.** Тред задачи просит тред «Ревью» проверить PR. Ревью отвечает «можно сливать» или списком замечаний; тред задачи их закрывает. Когда вердикт «можно сливать», тред задачи пишет в разделе «Ревью» описания PR строку «Ревью: пройдено (ссылка на вердикт)».
7. **Показ OTTO.** Снимки, что изменилось, что проверено. OTTO отвечает «сливай» или просит поправить.
8. **Слияние и выпуск.** Тред задачи сообщает треду 9; тот сливает и выпускает по [releasing.md](releasing.md).
9. **Запись.** Тред задачи обновляет память и документы, директор обновляет «Ход работ» и строку «СТАДИЯ». Тред закрывается.

## Слово OTTO

- Выбор, который меняет цель задачи: карточка с вариантами и рекомендацией.
- Слияние в `main`: только после «сливай».
- Удаление файлов, веток и данных: только после «да».
- Выпуск после слияния отдельного согласия не требует.

## Сабагенты

- Зовутся для задач крупнее одной правки: новая функция, несколько экранов, миграция. Мелкую правку тред делает сам, без сабагентов.
- Каждый сабагент получает в поручении постановку, ветку и критерии приёмки и сдаёт результат треду, а не OTTO.
- Ядро и фронтенд не работают в одной ветке одновременно: сначала ядро (команды и миграция), потом экраны.
- Карточки ролей лежат в `.claude/agents/`. Меняются они обычным PR.

## Статус и проценты

- Карточка статуса треда показывает общий процент и процент текущей стадии, обновляется при каждой смене стадии.
- В «Ходе работ» у каждой задачи видно, на ком она сейчас: «Тестировщик, 70 %» или «Ждём „сливай“».
