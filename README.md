# P-Treasury — десктопное приложение для личного и семейного бюджета

Стек и устройство описаны в [architecture.md](../architecture/architecture.md), состав функций в [mvp-features.md](../product/mvp-features.md), дизайн в [design/README.md](../design/README.md).

## Состояние

**Этап 0 (каркас) готов:**

- Rust-ядро `crates/core` без зависимостей от UI: SQLite (`rusqlite`, встроенный SQLite с FTS5), режим WAL, внешние ключи.
- Первая миграция `crates/core/migrations/0001_init.sql`: вся схема из раздела 4 архитектуры, включая таблицы версии 2, на которые есть ссылки (`recurring_rules`, `tags`), справочник валют и настройки по умолчанию.
- Миграции: версия в `PRAGMA user_version`, каждая миграция в своей транзакции, копия файла перед обновлением (хранятся последние 10), файл от более новой версии не открывается.
- Деньги: целые минимальные единицы, разбор ввода и формат «1 234,56» (`money.rs` и `src/lib/money.ts` дают одинаковый результат).
- Оболочка Tauri 2 `src-tauri` и интерфейс React + TypeScript: боковое меню в стиле A, пустые разделы, Ctrl+1…9, «Настройки → О программе» с версией приложения и данных.

**Этап 1 (учёт) готов:** мастер первого запуска, счета (в том числе кредитная карта с лимитом, валютные, закрытие, сверка с корректировкой), курсы валют и общий баланс в основной валюте, категории (два уровня, набор по умолчанию, удаление с переносом операций), операции (расход, доход, перевод между валютами с расчётом курса, получатель с подстановкой категории и счёта, фильтры и поиск по тексту и сумме), Главная. Горячие клавиши: Ctrl+N операция, Ctrl+T перевод, Ctrl+1…9 разделы, Ctrl+Enter сохранить.

**Этап 2 (бюджеты) готов:** бюджет на месяц с лимитами по категориям расходов и планом доходов, создание пустым или копированием прошлого месяца, план/факт/остаток с процентом и оранжевой отметкой перерасхода, операции в других валютах по курсу на дату, «Можно тратить сегодня», заметка к месяцу, переход из факта к операциям, краткий бюджет на Главной. Месяц считается от настройки «Месяц начинается» (например, с дня зарплаты); Главная тоже считает месяц от неё.

**Этап 3 (отчёты) готов:** период «месяц / квартал / год / произвольный» (месяцы от настройки «Месяц начинается»), доходы, расходы, сальдо и норма сбережений, структура расходов и доходов по категориям с подкатегориями, доходы и расходы по месяцам (график и таблица), остатки счетов на дату. Любая цифра открывает операции, из которых она сложилась. Норма сбережений также на Главной.

**Этап 4 (долги) готов:** калькулятор кредита (аннуитет и дифференцированный рядом, график, «Сохранить как долг»), долги «я дал / я взял» с процентами или без, аннуитет, дифференцированный или разовый возврат, график платежей, «Оплачено» (основной долг переводом, проценты расходом или доходом), частичный и досрочный платёж с выбором «уменьшить платёж / срок», просрочки, сводка «должны мне / должен я», чистые активы и ближайшие платежи на Главной.

**Этап 5 (календарь, напоминания, заметки) готов:** календарь месяца и недели (доходы и расходы дня, платежи по долгам, напоминания, заметки), панель дня с добавлением операции, напоминания и заметки на дату, итог месяца «ещё заплатить / ещё получить»; напоминания разовые и с повтором (ежедневно, еженедельно, ежемесячно в выбранное число, ежегодно), автоматические напоминания о платежах по долгам за N дней (настройка), «Выполнено», «Отложить», «Создать операцию» (сумма подставляется, для долга открывается «Оплачено»); системные уведомления, значок в трее (Открыть, Добавить операцию, Выход), сворачивание в трей при закрытии (настройка), окно пропущенных напоминаний при запуске; заметки с поиском по словам и привязкой к операции, долгу или дню; ближайшие напоминания на Главной.

**Этап 6 (данные и настройки) готов:** сводка за месяц, квартал, год или свой период в Excel (6 листов: Сводка, По категориям, Бюджет, По месяцам, Долги, Операции; суммы числами), кнопка «Выгрузить» в Операциях (по текущему фильтру) и Отчётах в .xlsx или .csv, импорт операций из CSV с предпросмотром и ошибками по строкам, шаблон импорта; резервная копия в файл, восстановление из копии с проверкой файла и сохранением прежних данных, автокопия при закрытии в выбранную папку (например, на Яндекс.Диске) с хранением последних N, напоминание о копии через месяц; проверка обновлений при запуске или по кнопке, установка с копией данных перед обновлением, «Что нового»; формат даты.

**Этап 7 (удобство) готов:** шаблоны операций («Кофе 250 ₽» одним нажатием на Главной, подстановка шаблона в форме, «Сохранить как шаблон»), арифметика в поле суммы (`1890+455` → 2 345 ₽, результат виден рядом с полем), отмена и повтор действий с данными (Ctrl+Z / Ctrl+Y, плашка «Отменить», до 50 шагов, с защитой от отмены изменённых позже данных), кнопка «Скрыть суммы» (Ctrl+H), справка по горячим клавишам (F1), поиск по Ctrl+F.

**Сравнение периодов (0.8):** Отчёты → «Сравнение»: два любых периода (или готовые пары «месяц к прошлому», «к тому же месяцу год назад», «квартал», «год»), по категориям, получателям или счетам; что стало больше и что меньше, на сколько в рублях и в процентах, новые и пропавшие позиции, выгрузка в Excel.

**Большой итоговый тест пройден** ([отчёт](docs/final-test-report.md)): полная регрессия, «месяц жизни», обновление со старой версии, 10 лет учёта, сбои посреди записи и копии. Тесты, которые запускаются отдельно:

```bash
cargo test --release -p budget-core --test volume -- --ignored --nocapture   # объём; KAZNA_VOLUME_DIR=папка оставит базу
KAZNA_VOLUME_DIR=папка node --test e2e/volume.test.mjs                        # окно на большой базе
KAZNA_OLD_BIN=путь/к/старой/сборке node --test e2e/upgrade.test.mjs           # обновление со старой версии
```

**Установщик для Windows** (`P-Treasury_0.8.0_x64-setup.exe`) собирается одним из двух способов:
- на GitHub: `.github/workflows/windows-installer.yml` (Actions → «Установщик для Windows»), ключ подписи обновлений кладётся в секрет `TAURI_SIGNING_PRIVATE_KEY`;
- на компьютере с Windows: `powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1` (что установить заранее, написано в начале скрипта).

**Дальше:** сборка установщика и ручная проверка по [списку](docs/owner-checklist.md).

## Как запустить

Нужны Node.js 22+, Rust 1.80+ и [системные зависимости Tauri](https://tauri.app/start/prerequisites/) (на Windows: WebView2 и Microsoft C++ Build Tools).

```bash
npm install
npm run tauri dev      # окно приложения с горячей перезагрузкой
npm run tauri build    # установщик для текущей ОС
```

Проверки (подробно в [TESTING.md](TESTING.md)):

```bash
npm run check        # формат, линтеры, все тесты ядра и UI, сборка
npm run check:e2e    # плюс сквозные тесты на настоящем окне (нужны tauri-driver и WebKitWebDriver)
```

Данные лежат в папке данных ОС: `%APPDATA%\app.kazna.desktop\budget.db` на Windows, `~/Library/Application Support/app.kazna.desktop/` на macOS, `~/.local/share/app.kazna.desktop/` на Linux. Копии перед обновлением: подпапка `backups`.

## Структура

```
crates/core/          ядро на Rust (вся логика и SQL)
  migrations/         нумерованные SQL-миграции
  src/storage/        открытие базы, миграции, резервные копии
  tests/              тесты ядра на настоящем файле SQLite
src-tauri/            окно Tauri и команды для UI (без SQL)
src/                  интерфейс React + TypeScript
e2e/                  сквозные тесты на настоящем окне (WebDriver)
scripts/check.sh      проверка всего проекта одной командой
```

Правило границ: UI вызывает только команды ядра, ядро обращается к базе только через `storage`.

Приложение называлось «Казна», с версии 0.8 — P-Treasury (папка данных прежняя, `app.kazna.desktop`, данные при обновлении остаются на месте). Иконка «Дверца сейфа» из треда дизайна (`design/icons/p-treasury/`).
